## 1. 我们现在到底做到了什么

你可以把当前系统理解为一个“电脑里的机械臂练习平台”：打开网页，拖动七个关节的滑块，画面中的机械臂会跟着动；调整夹爪滑块，夹爪会开合；暂停发送指令，程序会进入保持；最后把整个过程记录为数据文件。

它已经具有可运行的软件闭环，并且保留了通信、控制、数据和演示证据。它还不能通过接上一根线就控制实验室的 Franka 或 UR。

| 原项目目标 | 当前确实已有的内容 | 仍然缺少的内容 |
|---|---|---|
| GELLO 与 Franka/UR 硬件集成 | 虚拟输入、GELLO 可选接口封装、Panda 公开仿真模型 | 实物装配、串口测试、真机驱动、设备参数确认 |
| 动力学对齐 | 公共 Panda 模型中的惯性、重力、夹爪与碰撞几何 | 真实设备动力学辨识、负载标定、模型与实物的误差验证 |
| 同构运动映射 | 同关节数量/顺序下的方向、零位、比例映射；合成标定示例 | 实体手柄标定、实际姿态误差测量 |
| 低延迟交互 | 本机浏览器操作和本机双进程 UDP 验证 | 两台电脑、跨地域、视频回传和实际端到端延迟测量 |
| 示教轨迹采集 | 时间、状态、动作、目标、模式、完整性检查和 NPZ 导出 | 相机同步、真实任务标签、真实机器人任务数据 |
| 为模仿学习提供数据 | 本项目自己的结构化数据格式 | LeRobot/RLDS 转换、训练、模型评估 |
| 高精度与力反馈 | 仿真跟踪曲线和软件约束 | 实机末端精度、力传感器、双向力反馈 |

**关节角度对齐属于运动学映射，不等于动力学对齐。** 前者关注“哪个关节对应哪个、转多少”；后者还涉及质量、惯性、摩擦、力矩与真实响应。

结题没有规定必须交哪些文件，所以目前材料以答辩为中心组织。但“没有固定材料清单”不等于原项目的硬件目标自动取消。组长需要与指导老师确认：此次是否以“软件框架设计与仿真验证”作为汇报范围。

## 2. 这一版和上一版有什么区别

**v0.1 解决基础框架能否跑通；v0.2 增加具体的 Panda 模型、可操作界面和完整答辩展示。** 两版的核心映射思路一致。

| 对比项 | v0.1 | v0.2 | 对组员的实际意义 |
|---|---|---|---|
| 机器人模型 | 一阶简化模型、MuJoCo 通用关节链 | 新增公开 Franka Panda 模型 | 能看到接近 Panda 外形和结构的七关节机械臂 |
| 物理内容 | 通用链关闭重力与碰撞，夹爪是记录值 | Panda 保留惯性、重力、碰撞几何与原生夹爪 | 能演示模型中的关节与夹爪响应；不等于实物标定完成 |
| 操作入口 | 主要是终端命令和自动轨迹 | 新增浏览器七关节滑块及夹爪滑块 | 新手可以用鼠标演示，不必现场改代码 |
| 停止与恢复 | 软件状态机已有 | 界面提供暂停发送、急停、复位和重新使能 | 可以直接展示异常时的行为 |
| 通信 | 本机双进程 UDP 与网络扰动仿真已有 | 新增 Panda 后端的双进程验证 | 将原有通信链路接到 Panda 仿真 |
| 控制修正 | 原有关节范围、速度、加速度约束 | 增加固定目标附近的制动约束 | 修正固定目标参考轨迹过冲问题；没有完成新算法优越性对照 |
| 启动修正 | 虚拟输入可能在后端启动前推进 | 收到首个后端状态后再开始虚拟轨迹 | 减少 Panda 慢启动引起的初始对齐失败 |
| 测试证据 | 随包报告记录 23 项测试通过 | 随包报告记录 29 项测试通过 | 增加 Panda、界面引擎和回归问题的覆盖 |
| 数据样例 | `sample_episode/` 合成样例 | 新增 `manual_demo_episode/` | 有和视频、PPT 图表对应的 Panda 仿真日志 |
| 答辩材料 | 没有成套 PPT/视频 | 10 页 PPT、约 40 秒视频、讲稿问答、操作卡、截图与预览 | 可以直接开始彩排 |
| 实物与跨地域 | 未完成 | 仍未完成 | 不应向老师汇报成已经接通实体机械臂 |

逐文件核对原始两份压缩包：v0.1 有 39 个文件，v0.2 有 168 个；新增 129 个、修改 12 个、保留原样 27 个、删除 0 个。大量新增项是模型网格、图片与答辩资源，**不能把文件数量当成完成度**。精确改动表见 [VERSION_COMPARISON.md](VERSION_COMPARISON.md)。

两版中的测量对象和试验条件不同。例如旧版 UDP 服务器的 99.34 Hz 与新版浏览器演示的 99.26 Hz，不能直接当作性能提升或退步的证据。

这次团队说明更新还修正了验证报告里一个未替换的数组形状占位文字，并补充了 Panda 夹爪数据含义；没有更改控制代码、PPT、视频或原始实验日志。

## 4. 系统怎样工作

当前有两个入口，它们共享部分代码，但不要混为一种实验。

**浏览器入口：**鼠标拖滑块 → 网页通过本机 HTTP 发送角度 → 七关节映射 → 控制约束 → Panda 仿真运动。仿真状态反馈到网页，同时写入日志。这是大家最容易演示的路线，视频使用的就是它。

**双进程 UDP 入口：**操作端程序产生虚拟关节轨迹 → UDP 报文发送 → 机器人端程序检查有效期与使能 → 仿真执行并反馈。两个进程目前在同一电脑上验证；这条链路不是浏览器视频中的 HTTP 链路。

### 映射用一个例子理解

假设手柄某个关节的零位读数是 0.1 rad，当前读数为 0.3 rad，那么相对转动是 0.2 rad。若机器人对应方向一致、比例为 1，就在参考位置上增加 0.2 rad；若安装方向相反，就减去 0.2 rad。

代码支持：`目标角度 = 参考角度 + 方向 × 比例 × (输入角度 − 零位)`。

目前浏览器七个滑块直接对应 Panda 七个关节，采用恒等映射。六关节 UR 与七关节 Panda 不能少一个数或补一个零就互相转换；这种跨结构重定向尚未实现。

### 控制器和数据为什么分三种角度

你把滑块一下推得很远，只表示“想去那里”。控制器按速度、加速度和关节范围限制，生成当下这一拍允许执行的位置。MuJoCo 模型收到位置指令后，会产生自己的运动响应。

因此：`target` 是想去的位置，`action` 是这一拍下发的位置，`observation` 是执行前看到的位置。三者不必重合。浏览器显示的“最大关节跟踪差”是当前观测与目标的差，**不是 PPT 报告中的 RMSE 指标**。

## 6. 怎样检查和理解保存的数据

一次从启动到结束的完整记录叫一个 **episode**，可以理解为“一段录像”，只是里面主要装的是数值而非画面。

| 文件 | 白话解释 | 适合用什么看 |
|---|---|---|
| `steps.jsonl` | 每个控制步骤一行，记录状态和动作 | 文本编辑器可读；分析时用 Python |
| `metadata.json` | 这段记录的身份卡：时间、配置、单位、是否完整等 | 文本编辑器 |
| `summary.json` | 总行数、运行频率、状态变化等汇总 | 文本编辑器 |
| `episode.npz` | 给 NumPy 程序读取的数组文件 | Python；不能当 Excel 表格直接双击编辑 |

JSONL 内的 `observation.q` 等是**带点号的完整字段名**。一行先记录执行前的观测，再记录随后下发的动作。不能理解为“这一行 action 已经产生了这一行 observation”。

| 字段 | 解释 | 最容易误解的地方 |
|---|---|---|
| `observation.q` | 此刻七个关节的角度 | 当前模型状态，不是手柄输入 |
| `observation.dq` | 此刻关节速度 | `q` 是角度，`dq` 是角速度 |
| `action.q` | 这一拍准备执行的受约束目标 | 不等于最终已到达的位置 |
| `target.q` | 最新接受的原始目标 | 可能尚未实际执行 |
| `t_robot_s` | 机器人端相对时间，单位秒 | 不是北京时间，也不能直接与另一台电脑的钟比较 |
| `mode` | 当前状态，如 ACTIVE/HOLD | 决定该行是否属于执行区间 |
| `sample_weight` / NPZ 的 `valid` | 标记 ACTIVE 区间 | 不是“这个任务做对了” |
| `complete` | 本段记录是否完整写完 | 不代表抓取成功 |
| `success` | 任务是否成功的语义标签 | 当前为 `null`，意思是未知/未标注 |

交付的 `manual_demo_episode` 有 3517 行，其中 2302 行为 ACTIVE。数组 `observation`、`action`、`target` 的形状为 `(3517, 7)`：3517 个时刻、每个时刻 7 个关节。

可以直接检查交付样例：

```bash
python -m teleop inspect manual_demo_episode
```

想看数组结构的同学可运行：

```bash
python -c "import numpy as np; d=np.load('manual_demo_episode/episode.npz'); print(d.files); print(d['observation'].shape); print(int(d['valid'].sum()))"
```

这段数据由自动浏览器操作生成，元数据明确记录 `human_collected=false`。其中没有相机帧、实测力矩、真实抓取成功标签或训练结果。

后续做模仿学习，至少还要完成：选定实际任务 → 采集足够的有效演示 → 审核成功与失败 → 对齐相机和动作 → 转换训练框架要求的格式 → 按完整 episode 划分训练与验证 → 训练并评估。当前 NPZ 是起点，不能直接说“已经完成 Embodied AI 数据集建设”。

## 7. 测试与双终端通信怎么运行

### 7.1 先跑自动检查

在安装过依赖的工程根目录执行：

```bash
python -m unittest discover -s tests -v
```

交付版本报告记录了 29 项通过，末尾应有 `Ran 29 tests` 和 `OK`。你们自己跑时应保存实际输出；若失败，记录完整报错和环境，不要把随包报告当作本机通过证明。

### 7.2 不打开网页也可以自动仿真

```bash
python -m teleop sim --backend panda --output runs/panda-auto-01 --duration 6
python -m teleop inspect runs/panda-auto-01
```

`sim` 使用程序生成的输入。默认不按真实时间播放，6 秒模拟过程可能很快计算完；若需接近墙钟节拍，加 `--realtime`。网页演示请使用 `ui`，不要期待这条命令自动打开同一个网页。

### 7.3 一条命令验证本机 UDP

```bash
python -m examples.loopback_validation --backend panda --output runs/panda-udp-01
```

这个脚本启动操作端和仿真机器人端，检查收到运动指令以及输入结束后的 HOLD。检查生成的 `loopback.json` 中是否有通过标记；失败时保留输出。运行时先关闭视频编码、大型渲染等高负载任务；随包保留过一次重负载下的 `control_deadline` 故障。

### 7.4 想看两个终端分别在干什么

先在工程目录生成一次密钥：

```bash
python -m teleop keygen demo.key
```

若已经有这个密钥，复用即可，不要重复生成同名文件。密钥只是演示通信校验用，不要提交到 GitHub。

两个终端都进入同一个工程目录、激活同一个 Python 环境。先在终端 A 启动：

```bash
python -m teleop server --backend panda --config configs/panda_model.json --keyfile demo.key --output runs/server-01 --duration 30
```

然后尽快在终端 B 启动：

```bash
python -m teleop client --config configs/panda_model.json --keyfile demo.key --virtual --duration 20
```

终端 A 相当于“机器人旁的电脑”，但连接的仍是仿真；终端 B 相当于“操作员电脑”，但 `--virtual` 自动生成角度。两边实际上仍在同一台电脑上。等待程序结束，再检查 A 保存的数据。

两个终端只是两个程序窗口，不等于两台电脑。两台电脑和跨地域需要额外设置地址、网络和同步，并实测链路；当前没有对应验收结果。HTTP 界面也尚未部署为公网遥操作网站。

## 11. 常见问题

| 现象 | 优先检查与处理 |
|---|---|
| `conda: command not found` | 电脑可能没装 Conda，或当前终端没加载它；有 Python 3.10+ 可使用 venv 方案 |
| Python 版本是 3.9 | 更换到 3.10+ 环境；不要通过删版本检查强行安装 |
| `No module named teleop` | 确认环境已激活，且在有 pyproject.toml 的目录重新执行安装命令 |
| `No module named mujoco` / Pillow 相关缺失 | 当前环境还没装演示依赖；执行 `python -m pip install -e '.[demo]'` |
| 提示找不到 pyproject.toml | 当前目录不对；回到解压后工程根目录 |
| `FileExistsError` | 输出文件夹或密钥已经存在；采集换新目录，密钥则复用，不覆盖历史数据 |
| 网页打不开 / 连接被拒绝 | 终端程序是否仍运行？端口是否匹配？是否误把地址贴进搜索框？ |
| `Address already in use` | 旧服务仍占用端口；关闭自己之前的服务，或加 `--port 8081` 并打开对应地址 |
| 页面在但 3D 空白 | 检查浏览器 WebGL/图形加速、模型加载提示；不要直接双击 index.html |
| 滑块移动但机械臂不动 | 看状态是否 ACTIVE；暂停后恢复发送并再次开启跟随；急停后先本地复位 |
| 经常进入 HOLD 或 FAULT | 保留故障信息，关闭重负载程序，用小幅动作重试；不通过放宽阈值掩盖问题 |
| 结束保存后按钮都灰了 | 本段采集已经结束，是正常行为；退出后用新输出目录重新启动 |
| `inspect` 报完整性错误 | 保留原始目录与错误，检查保存是否完成；不要手改 metadata 让它看起来通过 |
| 新跑的行数不是 3517 | 3517 仅是交付视频那次的行数；自己运行时长和操作不同，行数不同正常 |
| PPT 的字挤在一起 | 检查目标电脑字体；可安装随包 Noto 字体后重开，并对照逐页 PNG |
| 为什么没有声音 | MP4 只有中文字幕，设计为讲解时配合播放 |
| GitHub 404 | 可能是地址不对、仓库改名/不存在或当前连接没获得仓库权限；先确认地址与授权 |

请把报错的**完整文字**、操作命令、Python 版本和系统一起记录，不要只发“跑不了”。不懂某段错误时先停在这里，交给组内环境负责人排查即可。
