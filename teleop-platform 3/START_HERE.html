全组零基础操作指南

版本：v0.3.0｜更新：2026-10-04｜适合没有机器人、Python 或 Git 经验的组员。

1. 先用一分钟弄清楚：我们手上有什么

这套材料目前是能运行、能演示、能保存数据的机器人遥操作仿真软件原型。电脑屏幕里有一台 Panda 机械臂，你用鼠标拖关节和夹爪，程序执行运动约束、显示反馈，并把全过程保存下来。

原项目还要求 GELLO 实物、Franka/UR 真机、动力学对齐和远程优化。这些不能因为仿真跑通就写成完成了。 当前没有真机驱动，软件会拒绝用占位接口启动真机；也没有完成模仿学习训练或任务成功率实验。

你们说结题只需要答辩、没有固定提交物。因此可以先准备基于已完成软件工作的真实汇报；是否足以结题仍由老师决定。最先请组长确认：“我们能否按软件框架与仿真验证汇报，并把硬件和跨地域实验列为未完成工作？”不能保证仅凭本包一定能结题。

每个人先做这三件事

  1. 看本指南第 1～3 节，知道已完成范围。
  2. 看 defense/panda-teleop-demo.mp4，理解操作流程。
  3. 读第 12 节常见问答，知道哪些话可以讲。

负责演示的人再做第 4～8 节；准备接设备的人再读第 11 节。其他人不需要先学习全部代码。

2. v0.3 和上一版有什么区别

事项 上一版 v0.2 这次 v0.3
安装与启动 复制安装、启动命令 启动文件自动准备独立环境，菜单选择
采集目录和端口 手动命名、遇到冲突自己改 自动生成新目录、自动选空闲端口
保存后检查 手动退出并检查日志 等待保存，自动结束服务并打开 HTML 报告
自动验收 普通测试可能显示 OK 但跳过可选项 自检遇到失败或跳过就不算全部通过
指令一致性 存在旧使能标记与重复输入检查缺口 每条运动指令检查当前使能标记、网页序号和控制页面
数据检查 检查行数和部分格式 增加配置哈希、字段约束、NPZ 与原始日志逐项比对
导出失败 页面可能显示“保存完成” 红色错误提示，保留原始记录，拒绝覆盖已有文件
测试 原有 29 项 41 项通过、0 跳过，新增缺陷回归测试
真机能力 未接通 仍未接通，不把软件修复当成硬件完成

这次主要提升可用性、检查完整性和错误处理；不是新的重定向算法，也没有证明控制精度或网络性能优于上一版。

3. 解压后先认四个入口

文件或文件夹 怎么打开 你需要知道什么

不要在压缩软件的预览窗口里直接运行。先全部解压到一个自己能写入的普通文件夹；例如桌面上的 teleop-platform。不要只取走 run.py：模型、网页、配置必须一起保留。

压缩包无法解压时：确认下载完成；重新下载完整 ZIP，或者使用同版 .tar.gz 备用包。不要只把 .tar.gz 改名成 .zip。无法判断时保留下载文件大小与报错截图。目录中的 MANIFEST.sha256 供技术负责人核对文件是否改变，普通组员不用手算。

4. 只做一次的环境准备

4.1 只看材料，不运行程序

只需能看网页、PPT 和 MP4。直接打开 START_HERE.html、PPT 和视频即可；不用 Python、Conda、Node.js、GELLO 或机械臂。

4.2 要亲手运行仿真

你需要一台普通电脑、Python 3.10 或以上、支持 WebGL 的浏览器，以及首次安装依赖时的网络。程序用浏览器显示三维模型，不要求购买机械臂或独立显卡。电脑太忙仍可能出现超时，后文有处理方法。

电脑 入口 本次验证情况
Linux 工程目录执行 bash START.sh Linux、Python 3.12 已实际验证
macOS 双击 START.command；有权限问题用下面的方法 已提供入口，未在你的 Mac 上实际验证
Windows 双击 START.bat 已提供入口，未做原生 Windows 实测

**已有 Python：**在终端输入 python --version 或 python3 --version，显示 3.10 以上即可继续。为减少旧依赖问题，优先使用现有的 3.11/3.12 环境。不要在答辩当天临时升级。

**已经有 Conda：**可在 Conda 终端逐行执行：

conda create -n teleop python=3.11 -y
conda activate teleop

然后进入工程文件夹，执行 python run.py。Conda 只是提供 Python；启动器仍会创建本工程自己的 .venv。如果已经有名为 teleop 的环境，直接激活，不用重复创建。

**完全没有 Python：**让环境负责人先安装适合这台电脑的 Python 3.11 或 3.12，并确认能执行上面的版本命令。Windows 安装时需让 Python 可以从终端启动。不要把所有组员都变成环境安装负责人；先准备一台稳定的答辩电脑即可。

4.3 “终端、进入目录”是什么意思

终端就是可以输入命令的窗口。每条命令输入后按回车；不要把代码框的三条反引号一起复制进去。

macOS：打开“终端”，输入 cd （d 后有一个空格），把解压后的工程文件夹拖进终端，再回车。然后输入：

bash START.command

这种方式不需要你手动修改执行权限。若系统询问是否允许来自下载内容的文件，按你们电脑的管理规则处理；受学校管理的电脑交给管理员。

Linux：在工程文件夹空白处打开终端，输入：

bash START.sh

Windows：通常双击 START.bat。若窗口提示缺少 Python，在该文件夹打开 PowerShell，输入 py -3 --version 或 python --version，把完整结果交给环境负责人。

5. 第一次启动：先选 2 自检

启动后看到菜单：

机器人遥操作仿真 v0.3
1 开始演示并采集
2 自动检查软件与数据链路
3 检查最近一次采集
4 打开零基础指南
0 退出

输入 2，按回车。第一次会联网下载依赖；看到安装文字属于正常现象，请等命令结束。程序只在工程里创建 .venv，不要求你手动安装一串包。

完成后会自动打开报告。没有自动弹出时，复制终端显示的 report.html 完整路径，或从 runs/checks-日期时间-编号/ 打开。

报告项目 大白话解释 通过意味着什么
环境与模型 Python、依赖和机械臂模型能加载 运行所需资源基本齐全
全部测试且无跳过 跑 41 项检查 没有失败、报错或因缺依赖而跳过
Panda 运动、采集与 NPZ 一致性 自动动一下并保存，比较两种文件 软件和数据链路能配合
本机 UDP 跟随与断流保持 两个本机进程互发指令，模拟停发 本机通信及对应状态变化能工作

看到“本机软件自检通过”再开始下一步。自检未通过就看报告的具体项目；不要把跳过当成通过，也不要修改测试让它变绿。

自检不是答辩电脑图形显示验收，也不是实体机器人安全验收。下一步仍要由你亲手打开网页、操作一次。

每次菜单选择完成后脚本退出；需要做下一项时重新打开启动文件。按提示回车关闭终端窗口即可。

6. 开始你们自己的第一次演示

重新启动，输入 1 回车。程序自动创建新的采集目录和本机网址，一般自动打开浏览器。没有打开，就复制终端里 http://127.0.0.1:数字 的整行网址到浏览器地址栏；每次数字可能不同，不要照抄别人上次的端口。

127.0.0.1 意思是“这台电脑自己”。这不是组员共享网址，也不能用来隔着互联网控制机械臂。

按这个顺序操作

步骤 你要做什么 应该看到什么
1 等待三维机械臂和右侧滑块出现 提示“Panda 模型已加载”，状态“未使能”
2 点击“开启跟随” 状态变为“跟随中”；滑块先对齐当前姿态
3 把关节 1 从 0 附近轻移到约 0.2 rad 模型平稳跟随；不要一下拖到最左/最右
4 把夹爪滑块调到约 50%，等待，再调回 手指开合；下面记录数量持续增加
5 点击“暂停指令发送” 短暂等待后状态变为“保持”
6 点“恢复指令发送”，再点“开启跟随” 恢复跟随；只恢复发送不会自行开始运动
7 点“软件急停” 显示“急停锁定”；这是仿真按钮
8 点“本地复位” 回到“未使能”，不会自己恢复运动
9 点“结束并保存”并等待 成功显示“轨迹已结束并完整保存”
10 等几秒 启动器自动结束服务，打开这次采集的数据报告

同一时间只保留一个控制页面。多个页面同时控制会被拒绝；若误刷新导致“另一页面正在控制”，先关闭多余页面，再点“本地复位”后重新开启跟随。

如果保存出现红色“未全部完成”，这次不算保存成功。不要删除目录，保留页面错误和终端文字，按第 9 节处理。

关闭浏览器标签页只会停止指令输入，不会主动结束后台记录。正常结束应点“结束并保存”。万一已经关掉页面，仍可用终端显示的网址重新打开，或在运行终端按 Ctrl+C 请求正常退出并保存；不要直接强制结束进程或关机。

上面的菜单入口会自动结束服务；旧式 python -m teleop ui 命令仍需保存后按 Ctrl+C，所以初学者统一使用启动菜单。

7. 保存的数据在哪里，怎么知道可用

工程里会出现 runs/manual-日期时间-随机编号/，每次都不同，程序不会覆盖你上一次的数据。

文件 比喻 要不要自己编辑
steps.jsonl 一行一行的运动流水账 不要；原始证据
metadata.json 这段记录的说明标签 不要直接改；包含配置和校验信息
summary.json 这次运行的统计摘要 查看即可
episode.npz 给 Python/训练程序读的打包数组 无需手动打开，更不用解压它来演示
quality-report/report.html 给人看的检查结果 双击浏览器打开
quality-report/report.json 给程序读的检查结果 技术人员使用

报告说“数据完整性检查通过”，表示原始日志、配置、有效行和 NPZ 对得上。不表示机器人完成了抓取，也不表示这些数据已经可以直接训练一个可靠策略。

你可以核对：总行数大于 0、ACTIVE 行数大于 0、关节数为 7；如果你确实拖动了机械臂，各关节运动范围应有非零值。只开页面不动就保存，完整性可以通过，但会提示没有有效跟随或几乎没有运动，这不是程序自相矛盾。

报告默认提示“任务成功未标注”“没有已确认的人工采集身份”，是因为程序不知道是谁在操作，也没有判断抓取成功。真实由你手动操作时，另记操作者、日期、任务和这次文件夹名，交给数据负责人审核；不要为了消掉提示篡改 JSON 或把 success 随手改为 true。

菜单 3 可以重新检查 runs 里最近一次采集；它会新建独立检查报告，不覆盖旧报告。需要检查指定旧记录时交给技术负责人用：

python -m teleop quality 路径到某次采集 --output 一个尚不存在的报告目录

该命令要使用项目环境。普通组员用菜单即可。

8. 答辩当天怎么安排

提前一天

  1. 组长确认答辩时长、是否允许按仿真阶段汇报，以及姓名/单位等必要信息。
  2. 环境负责人在实际答辩电脑上先选 2，再选 1 按第 6 节完整做一次，保留自己的 runs 目录。
  3. PPT 负责人打开 defense/robot-teleop-defense.pptx 逐页检查；视频从本机磁盘能播放。字体错位时可安装 defense/fonts/ 中附带的字体，再重开演示软件。
  4. 全组做一次限时彩排。每个人至少能解释“已经做成什么、哪些没做”。

现场

先讲“这是软件框架与仿真验证”。可用第 5 页引出演示，按第 6 节做一分钟流程。演示时避免同时开游戏、视频编码或其他高负载软件。

出现电脑或投影问题时，直接播放 panda-teleop-demo.mp4，明确说明是预先录制的仿真演示，展示随包的历史日志。不要把播放视频说成现场实时控制。

PPT 共 10 页；逐页讲法和问答在 defense/defense-script-and-qa.md，每页也有备注。旧视频约 40 秒，没有配音，可边播边讲。它由自动脚本操作真实网页录制，不是人类示教实验，更不是实体机械臂实验。

数字怎么讲，避免混用

  • 41 项测试通过、0 跳过：v0.3 当前软件回归结果。
  • 3517 行、2302 行 ACTIVE、约 99.26 Hz、约 115.9 ms 到 HOLD：随包 v0.2 演示那一次运行的数据，仍可展示，但要标明历史演示。
  • 你们新采集的行数、频率会变化，应讲自己那次报告的结果，不能为了匹配 PPT 去改日志。
  • v0.3 数据报告的平均频率用 (行数−1)/(末时间戳−首时间戳)；旧演示摘要用 行数/总墙钟时间，分母包含范围不同，所以数值不完全一样。

12. 答辩最常见的十个问题

老师可能问 可以如实这样答
做成了什么？ 完成了 Panda 遥操作软件原型与仿真验证，包括输入、约束、状态机、记录和导出。
机械臂和 GELLO 接上了吗？ 这版未接实体设备；GELLO 只有待验证输入封装，Franka/UR 真机驱动尚未完成。
创新在哪里？ 这次贡献主要是流程集成、数据检查、失效处理和可复现交付，不声称发明新的同构映射算法。
同构映射是什么？ 关节数和结构对应时，把每个操作关节按零位、方向和比例换算到机器人关节。
UR 是六关节，Panda 七关节怎么办？ 不能直接逐关节映射；现在会拒绝不匹配输入，异构重定向还未实现。
低延迟证明了吗？ 目前只有本机仿真与通信测量；不能当成跨地域单向时延结论。
高精度怎么证明？ 日志可计算关节跟踪误差；尚无实机末端精度或外部测量结果。
为什么断流不自动恢复？ 进入保持后要求重新对齐和人工使能，避免旧输入直接重启运动。
数据能训练吗？ 已保存关节观测、动作、时间和有效掩码；还没完成视觉数据、任务标签、LeRobot/RLDS 转换和训练评估。
下一步是什么？ 先确认设备并完成本地只读/停止/标定，再做受限实机跟随和真实任务数据。
