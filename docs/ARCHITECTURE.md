# 架构、算法与边界

## 控制链路

操作端采样手柄，完成关节标定映射；机器人端只接受当前会话、合法签名、序号递增且仍有效的目标。机器人端本地状态机产生受限参考轨迹，后端执行，再向操作端返回状态。远程链路承载目标与状态；最终真机伺服必须留在机器人旁的控制主机。

本次默认上层控制 100 Hz。它是设计配置，不是对任意系统的频率保证。Franka FCI 官方文档要求本地低延迟控制；UR RTDE 的输出频率上限与实际运动控制路径不是同一个概念，不能把“能收到 500 Hz 状态”当成“Python 远程进程已有 500 Hz 安全伺服”。

## 映射与“动力学对齐”

同构映射使用同关节数、顺序与运动学拓扑。`q_r = r + s*g*(q_l-o)`，每项均按关节逐元素运算。标准关节角映射的比例通常从 1 开始，而不是用臂长比例随意缩放。实际设备需量测方向与零位，判断机械结构与坐标定义一致性。

多姿态标定按关节拟合 `q_r=a*q_l+b`。程序输出 `s=sign(a)`、`g=abs(a)`、`o=-b/a`，并报告拟合残差。留出姿态的误差、编码器量化与回差需要另测。该模型不能补偿柔性、摩擦、背隙、温漂与负载变形。

质量、质心、惯量、摩擦与重力补偿属于动力学，不由编码器零位标定解决。当前没有动力学辨识或双向力反馈。应把原任务中的“动力学对齐”改写成先交付“运动学结构匹配与关节标定”，然后单列有硬件依据的动力学工作。

## 新鲜度与时间

机器人每个控制周期签发随机 challenge，记录**自己的**到期时间。客户端收到 challenge 后才读取手柄、生成目标，再带原 challenge 发回。机器人用自己的单调时钟检查 challenge。默认有效期 120 ms，接收看门狗为 150 ms；两者先到者生效。

因此即使网络持续迟到旧指令，也不能只靠“最近有包抵达”来延长执行。跨主机不计算 `机器人 monotonic - 操作端 monotonic`。在诚实客户端按协议新采样的前提下，challenge 往返时间给出采样年龄上界；它不证明某个外部传感器内部没有缓存旧样本。真机采集还需传感器时间戳与质量检查。

序列号防止同一客户端的乱序与重放；随机会话隔离服务器重启；HMAC 校验消息完整性。网络读取每周期最多 64 包，避免包洪泛完全挤占看门狗。未实现重传过期控制目标；目标只在其有效期内有意义。

默认 RTT 预算很保守，较大跨地域 RTT 可能导致系统拒绝使能。这是当前配置下的可用性限制。不能仅增大超时就宣称解决远程优化；超时越大，潜在继续运动时间越长。需要用任务允许的停车距离重新设计预算。

## 状态机

| 状态 | 进入条件 | 恢复条件 |
|---|---|---|
| DISARMED | 启动或本地 reset | 有效新鲜目标、手柄与当前位置对齐、当前 arm epoch |
| ACTIVE | 成功使能 | 持续有效输入 |
| HOLD | 有效期到期、断流、松开使能 | 对齐并显式重新使能；旧 arm epoch 失效 |
| ESTOP | 有效急停请求 | 本地 reset；网络不能 reset |
| FAULT | 控制周期超限、跟踪误差、位置越界 | 本地排障与 reset |

CLI 未暴露网络 reset；仿真服务器重启是目前简便的本地恢复方式。真机状态必须映射到厂家控制器的状态与恢复流程。

## 运动约束

正常 ACTIVE 模式：目标必须在配置的位置范围内，参考速度限制为各关节 vmax，加速度变化限制为 amax*dt。使用保守离散制动距离约束减小接近关节边界和目标位置时的速度。目标突然跳到当前运动方向之后时仍保留加速度限制，不承诺对任意移动目标无过冲。若内部约束仍被破坏，进入 FAULT。未实现 jerk 限制、笛卡尔工作空间、自碰撞/环境碰撞、扭矩限制或末端力限制。

toy、通用 MuJoCo 与 Panda 模型 在 HOLD/FAULT/ESTOP 中数值冻结速度，以检验上层时序。这**不是物理机器人的停车实现**，不能用于测量真实制动距离，也不保证停车瞬间的加速度约束。真机需本地受控减速、厂家停止接口和实体急停。Python/GIL/GC/磁盘线程均不提供硬实时保证。

## 数据与故障隔离

记录器使用有界队列与单写线程。队列满或写入故障会显式报错，控制主循环 finally 关闭仿真后端，episode 标为不完整；不静默丢行。元数据初始 `complete=false`，正常关闭才置真并记录 SHA-256。进程崩溃仍可能丢最后未落盘的行；完整标记和哈希使其不能当作正常示教自动导出。它不是具备 fsync 的断电事务系统。

加速离线仿真允许有界等待写盘，避免生成速度超过磁盘时失去复现数据；在线服务器和按真实时间播放的仿真不走此等待路径。离线 compute_per_tick 包含可能的写盘等待，不能外推为硬实时控制性能。

协议中的 `Robot` 是本地适配契约；真实驱动应增加明确的错误状态、关节/工具状态、时间戳和 stop 结果。当前 `RealRobotUnavailable` 会拒绝启动，避免把模拟停止误当成硬件停止。

## v0.2 本地交互入口

`manual.py` 提供只监听 127.0.0.1 的 HTTP 界面。主页面请求模型和绘图姿态，Web Worker 独立请求短有效期并发送七关节滑块目标；Python 线程负责控制、Panda 物理推进和异步记录。软件急停与 reset 按钮为同机本地动作，写请求要求随机 token。它不是公网 Web 遥操作部署。公开模型保留重力、惯性和夹爪，不代表实机动力学对齐或主动避碰。

## v0.3 审查修复

每条 ACTIVE 运动命令也验证当前 arm epoch；网页命令增加客户端递增序号与单页面持有控制，复位后清理持有者。`manual.py` 单独检查真实墙钟间隔，避免固定物理积分步长掩盖控制线程迟到。先绑定 HTTP 端口再创建模型和记录器，启动失败会清理已分配资源。

启动器管理项目独立环境和唯一输出目录；严格自检不接受跳过测试。数据质量报告检验配置和 NPZ 与原始日志一致性。保存状态区分完成收尾与退出请求，导出失败明确可见。新增机制仍是软件原型验证，不构成实体机器人安全认证。
